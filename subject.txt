Description Write a shell
Your shell should:
• Display a prompt when waiting for a new command.
• Have a working history.
• Search and launch the right executable (based on the PATH variable or using a
relative or an absolute path).
• Use at most one global variable to indicate a received signal. Consider the
implications: this approach ensures that your signal handler will not access your
main data structures.
Be careful. This global variable must only store the signal number
and must not provide any additional information or access to data.
Therefore, using "norm" type structures in the global scope is
forbidden.

◦ << should be given a delimiter, then read the input until a line containing the

◦ >> should redirect output in append mode.
• Implement pipes (| character). The output of each command in the pipeline is

• Handle environment variables ($ followed by a sequence of characters) which
should expand to their values.
• Handle $? which should expand to the exit status of the most recently executed
foreground pipeline.
• Handle ctrl-C, ctrl-D and ctrl-\ which should behave like in bash.
• In interactive mode:
◦ ctrl-C displays a new prompt on a new line.
◦ ctrl-D exits the shell.
◦ ctrl-\ does nothing.

◦ echo with option -n
◦ cd with only a relative or absolute path
◦ pwd with no options
◦ export with no options
◦ unset with no options
◦ env with no options or arguments
◦ exit with no options

1. Unclosed quotes — MANQUANT
Le sujet dit : "Not interpret unclosed quotes". Actuellement, echo "hello supprime silencieusement le guillemet et affiche hello. Il faut détecter et refuser les quotes non fermées avec une erreur et $? = 2.

2. Syntax errors ne set pas $? à 2 — ISSUE
Dans parse_syntax.c, les erreurs de syntaxe (| cmd, > >) affichent un message mais ne mettent jamais g_exit_status = 2. Bash le fait.

3. export sans argument — affichage incorrect — ISSUE
export seul affiche declare -x VAR=value au lieu de declare -x VAR="value" (les valeurs doivent être entre guillemets). L'ordre alphabétique est aussi attendu par bash.

4 FIX . Ordre des redirections < / << non préservé — ISSUE
setup_redirections() applique toujours heredoc en premier, puis infile. Donc cat < file << EOF utilise file au lieu du heredoc. La dernière redirection d'entrée (de gauche à droite) devrait gagner.

5 FIX . Signal non restauré après heredoc builtin — ISSUE
Après un heredoc dans un builtin sans fork (ex: echo << EOF), le signal SIGINT est mis à SIG_DFL mais jamais restauré à handle_sigint. Un Ctrl+C après ça tue le shell au lieu d'afficher un nouveau prompt.

6 FIX . exit overflow — mineur
ft_atoi() ne détecte pas l'overflow. exit 9999999999999999999 devrait afficher "numeric argument required" et quitter avec 2, comme bash. 

7. Heredocs dans pipelines — ISSUE
Avec cat << A | grep << B, les enfants lisent les heredocs en parallèle (race condition). Bash lit tous les heredocs séquentiellement avant de fork.
